# 五条口诀详细检查清单

每次讲解一道 Java 大题时，必须读取本文件。五条口诀都要结合用户当前题讲解，不要只贴通用规则。

## 通用讲解模板

讲解每条口诀时使用以下顺序：

1. 展示口诀原句。
2. 说明什么时候使用。
3. 指出用户当前题里的真实位置和代码。
4. 按对应检查清单逐项追问。
5. 把检查结果转换成当前空位的答案。
6. 给弱基础用户补充一个最小必要知识点。
7. 给一条易错提醒或自检问题。

## 一、看到类，就问“哪里 new 了它”

什么时候使用：

- 代码或类图中出现一个类，尤其是普通具体类。
- 类已经完整写好，却看不到对象创建位置。
- 空位可能是变量初始化、参数、表达式或返回值，需要判断是否应该创建对象。

按这个顺序问：

1. 这是普通具体类吗？
2. 代码里有没有 `new 类名()`？
3. `new` 的参数是什么，能否反推类型？
4. `new` 出来的对象赋给了谁？
5. 如果完全没被 `new`，它是接口、抽象类、枚举还是入口类？
6. 如果都不是，而且代码里还有空，这个空很可能就是创建它的位置。

注意：这个口诀不是绝对规律。接口、抽象类、枚举、工具类和 `Main` 类都不一定需要 `new`。但在软考这种代码填空中，对于已经完整实现、却没有被创建的普通具体类，“找哪里 `new` 了它”非常有效。

结合当前题时必须指出：

- 当前题有哪些普通具体类。
- 哪些类已经出现 `new`，构造参数是什么，对象赋给了谁。
- 哪些具体类完全没有创建位置。
- 哪个空最可能负责 `new`，为什么不能改成创建接口或抽象类。

弱基础补充：

- `new` 负责创建对象并调用构造方法。
- 左侧变量类型和右侧实际对象类型可以不同。
- 接口变量可以指向实现类对象，但不能写 `new 接口()`。

## 二、看到接口或抽象类，就问“哪个子类实现了它”

什么时候使用：

- 看到 `interface` 或 `abstract class`。
- 看到接口或抽象类类型的变量。
- 看到没有方法体的抽象方法。
- 某个具体类写了 `implements` 或 `extends`。

按这个顺序检查：

1. 看到接口，搜索 `implements`。
2. 看到抽象类，搜索 `extends`。
3. 找到所有实现类或子类。
4. 对比它们共同实现的方法，反推接口或父类中的抽象方法。
5. 查看接口或抽象类类型的变量。
6. 判断变量实际指向哪个具体类。
7. 再回到具体类，找它在哪里被 `new`。
8. 最后检查方法名、返回值、参数是否完全匹配。

结合当前题时必须指出：

- 当前接口或抽象类叫什么。
- 哪些类实现或继承了它。
- 这些实现类共同提供了什么方法。
- 接口或父类空位应填的完整方法声明。
- 接口变量最终保存的是哪个具体类对象。
- 具体类在哪个空位被创建。

弱基础补充：

- 接口主要规定“必须有什么方法”。
- 抽象类可以同时包含抽象方法和普通方法。
- 接口方法通常没有方法体，`abstract` 是隐式的。
- 接口变量只能直接调用接口中声明的方法。

## 三、看到属性，就问“哪里设置值、哪里读取值”

什么时候使用：

- 类中声明了成员属性或字段。
- 出现 `this.field = ...`。
- 出现 getter、setter、构造方法赋值。
- 属性是 `private`，外部代码需要读取或修改数据。

如果代码中出现了一个属性：

```java
private String name;
```

按顺序检查：

1. 有没有在声明时赋值？
2. 有没有在构造方法中赋值？
3. 有没有 setter 给它赋值？
4. 有没有在类内部直接读取？
5. 有没有 getter 暴露给外部类读取？
6. 这个 getter 有没有被其他地方调用？

如果发现有调用：

```java
person.getName();
```

但代码中没有 `getName()`，那这个空位很可能就要填 getter：

```java
public String getName() {
    return name;
}
```

如果发现外部调用：

```java
person.setName("Tom");
```

但没有 `setName()`，空位通常就填：

```java
public void setName(String name) {
    this.name = name;
}
```

结合当前题时必须指出：

- 属性名和类型。
- 写入位置。
- 读取位置。
- 外部读取或写入的调用点。
- 如果读写链断开，哪个空负责补齐。

弱基础补充：

- 属性属于对象，参数和局部变量只属于方法执行过程。
- `this.name` 通常表示当前对象的属性。
- 构造方法也可以承担 setter 的功能。

## 四、看到方法，就问“哪里调用它”

什么时候使用：

- 出现方法声明。
- 出现 `对象.方法()`、`类名.静态方法()` 或同类内的方法调用。
- 方法已经实现，却暂时没有调用点。
- 调用点存在，但方法声明缺失。

看到方法后依次问：

1. 谁调用它？
2. 调用者通过什么对象调用？
3. 接收者变量是什么类型？
4. 实际传了几个参数？
5. 这些参数分别是什么类型？
6. 调用结果是否被保存、返回或参与判断？
7. 方法声明和调用是否完全匹配？

可以浓缩成：

```text
找调用者 -> 看接收者类型 -> 看实参类型 -> 看返回值用法 -> 比对方法声明
```

结合当前题时必须指出：

- 每个方法声明对应的调用点。
- 哪些方法已有实现但没有调用点。
- 哪个空需要补调用。
- 调用者类型如何决定方法属于哪个类或接口。
- 实参类型如何决定参数类型。
- 返回结果如何使用，如何决定返回类型。

弱基础补充：

- 构造函数也是一种方法，由 `new` 调用。
- `void` 表示不返回结果；有返回类型时通常需要 `return`。
- Java 严格说方法签名包括方法名和参数类型，但考试填空通常还要写返回类型。

## 五、看到参数，就问“方法体有没有使用它”

什么时候使用：

- 方法或构造方法签名中存在参数。
- 方法体为空，或某个参数看起来没有被使用。
- 需要在空位中决定如何传入或使用参数。
- 方法重写时，需要核对参数类型是否一致。

看到参数后依次问：

1. 参数叫什么名字？
2. 参数类型是什么？
3. 方法体内有没有出现这个参数？
4. 它是作为方法接收者、实参、赋值来源，还是判断条件？
5. 它调用了哪些方法？
6. 那些方法应该属于哪个类或接口？
7. 如果参数没有使用，哪个空最可能需要用到它？
8. 方法重写时，子类和接口的参数类型是否完全一致？

参数常见使用形式：

```java
param.method();       // 作为方法接收者
other(param);         // 作为另一个方法的实参
field = param;        // 给属性赋值
if (param) { }        // 作为条件判断
return param;         // 作为返回值
```

结合当前题时必须指出：

- 方法有哪些参数，分别是什么类型。
- 每个参数在方法体中的实际使用位置。
- 没有使用的参数与哪个空相关。
- 从 `param.method()` 反推出参数类型必须具有什么方法。
- 重写方法的参数是否一致。

弱基础补充：

- 定义方法时叫参数，调用时传入的值叫实参。
- 参数只在所属方法内部有效。
- 接口实现和父类重写不能随意改变参数类型。
